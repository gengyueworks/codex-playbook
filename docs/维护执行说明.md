# 教程长期维护执行说明

这份文件给作者和定时 Agent 共用。它规定谁做什么、结果放在哪里、哪些动作需要人工确认。

## 分工

### GitHub Actions

只负责机械检查：

- 运行 `scripts/quality_gate.py`。
- 检查 Markdown 链接、章节数量、双语文件、示例 JSON 和表格格式。
- 在 Pull Request 和 `main` 分支更新时运行。

它不会生成正文，也不会自动合并内容。

### 每周维护 Agent

负责发现问题和生成维护报告：

- 查看 GitHub Issues、最近提交和路线图。
- 运行质量门禁。
- 找出一项最值得处理的问题。
- 把调查结果写进当月维护报告目录。
- 给出下一步任务单。

它默认只生成报告和草稿，不修改主书、不提交、不推送。

### 每月案例 Agent

负责把一个真实经历整理成双语案例和练习：

- 只处理一个案例。
- 先确认事实和可公开范围。
- 生成中文案例、英文对应稿和脱敏练习。
- 运行质量门禁。
- 等作者审阅后再进入主书或案例目录。

### 作者

负责最终判断：

- 案例是否真实，能否公开。
- 文章是否像自己的声音。
- 数字、日期和链接是否准确。
- 是否需要修改主书。
- 是否提交和推送。

## 目录约定

```text
docs/maintenance/
├── weekly-agent-prompt.zh-CN.md
├── monthly-case-agent-prompt.zh-CN.md
├── reports/
│   └── YYYY-MM/
│       └── YYYY-MM-DD-weekly.md
└── drafts/
    └── YYYY-MM/
        └── YYYY-MM-DD-case-name/
```

报告和草稿按月份归档，避免根目录堆积。

## 每周任务的完成标准

- 有一份当日维护报告。
- 质量门禁有明确结果。
- 至少检查 Issues、路线图和最近一次版本说明。
- 报告列出一个优先任务、理由和下一步。
- 没有改动主书或推送远程分支。

## 每月案例的完成标准

- 有中文案例和英文对应稿。
- 有脱敏输入和读者练习。
- 记录真实日期、输入、结果、失败点和验收方式。
- 没有账号、密钥、私人邮箱或本机路径。
- `scripts/quality_gate.py` 和 `git diff --check` 通过。

## 维护产出推送规则

纯维护产出在满足以下全部条件时，Agent 可以提交并推送，无需等作者确认：

- 质量门禁（`scripts/quality_gate.py` 和 `git diff --check`）通过；
- 不含个人信息：账号、密钥、私人邮箱、本机路径、未公开材料；
- 没有修改 `playbook/zh/` 或 `playbook/en/` 主章节；
- 不删除或重命名公开文件；
- 不更改 GitHub Actions 权限。

适用内容：维护报告、草稿、贡献指南、路线图勾选、README 与文档的小修小补。

凡是涉及主书正文、案例事实、个人信息或未核实事实的内容，仍然必须停在草稿阶段，等作者确认后再推送。推送后内容即公开，无法收回，这是信息暴露的主要风险点。

## 人工确认点

以下动作必须停在草稿阶段，交给作者判断：

- 修改 `playbook/zh/` 或 `playbook/en/` 主章节。
- 删除或重命名公开文件。
- 发布带有真实账号、个人经历或未公开项目的信息。
- 提交和推送 GitHub。
- 更改 GitHub Actions 权限。
