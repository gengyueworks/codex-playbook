# 任务驱动：需求表述规范

> 消化自雨哥 Codex 实战课第 2、3、7 节，叠加橙皮书边界约束方法论。

---

## 理解 AI 的认知模型

在写提示词之前，先理解 AI 的特点：

**AI 像一个读过很多书但没真正生活过的超级学霸。** 你问它知识，它能说；让它写文章，它很快；让它列框架，它很熟。但它不知道你的公司、你的客户、你的风格——除非你告诉它。

这就是为什么只丢一句"帮我写个东西"然后期待它完全懂你是不可能的。**同一个 AI，两种提示词，两种完全不同的结果。**

---

## 指令结构

```
角色 + 目标 + 上下文 + 验收标准
```

**示例：**

> 你是前端开发者。优化首页首屏的标题、副标题和 CTA 按钮。
> 项目在 `src/`，使用 React + Tailwind。当前问题：首屏转化率低，用户不清楚产品卖点。
> 验收标准：① 标题表达清晰、② CTA 按钮视觉突出、③ 移动端 375px 下布局正常、④ 不影响其他页面、⑤ 项目可正常构建。

---

## 边界约束

| 约束类型 | 示例 |
|---|---|
| 文件范围 | 只改 `components/Hero.tsx` 和 `globals.css` |
| 逻辑保护 | 不要修改登录认证流程 |
| 接口保护 | 不要更改 API 请求路径 |
| 依赖保护 | 不要升级或新增依赖包 |
| 页面保护 | 不要影响 `/login` 和 `/settings` 页面 |

缺少边界约束是需求偏移的首要原因。AI 不知道哪些东西对你重要，必须显式告诉它。

## 表述对比

| 模糊表述 | 准确表述 |
|---|---|
| 优化首页 | 优化首页首屏的标题、副标题和 CTA 按钮的文案与样式 |
| 页面不好看 | 调整卡片的间距（从 16px 到 24px）、标题字号（从 18px 到 22px） |
| 登录有问题 | 修复点击登录按钮后页面未跳转的问题（预期：跳转至 `/dashboard`） |
| 做一个后台 | 新增用户列表页，包含：搜索框、状态筛选、分页（每页 20 条） |

## 从模糊提示词到精确提示词：迭代法

不要试图一次性写出完美提示词。实战课程里验证过的路线是：

**第一轮：让 AI 帮你诊断缺失。**
输入你目前能给出的最完整的指令，然后问它：这个任务还缺哪些关键信息才能执行？

**第二轮：你补充缺失信息。**
培训主题、时间地点、目标对象、语气风格、字数限制——AI 会列出缺什么，你逐项补充。

**第三轮：AI 给出精确版本。**
信息齐全后，AI 的输出质量会有质的提升。

**第四轮：沉淀为模板。**
这条经过验证的提示词模板，下次同类任务直接复用，不再从头迭代。

**核心认知**：精确提示词不是"一次性写对的"，而是"一轮轮迭代出来的"。模糊输入→AI 诊断→补充信息→精确输出→沉淀模板，这五步是需求表述的完整闭环。

## 上下文和多轮对话

AI 在对话中能记住前面说过的东西（上下文），但上下文长度有限。聊得太长、塞的材料太多，前面的内容可能被顶掉。

**不要指望一次问完得到完美答案。** AI 最好用的地方不是"一次搞定"，而是"可以一直改"——太长就压缩到 200 字、太正式就改口语一点、需要数据对比就加表格、发现漏洞就换角度检查。

**更高效的用法**：先说目标，再给关键材料。不要一上来复制一整本书。

---

## Token 意识

Token 可以简单理解为 AI 处理文字时消耗的容量单位。你输入越多、要求输出越多，消耗也越多。

不是让你吝啬 Token，而是建立意识：**每一次对话都是一次资源投入。** 把 Token 花在描述清楚任务上，而不是花在反复修改模糊指令带来的低效迭代上。
