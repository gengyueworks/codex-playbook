## 8. 实战工作流

### 8.1 写作到仓库

将原创内容转化为开源项目的标准化流程：

1. 完成原创内容的 markdown 文件
2. 使用 Codex 生成项目骨架：README、目录结构、导航索引
3. 组织内容文件到对应的目录结构
4. 生成封面或入口页面（如 `index.html`）
5. 执行 `git push` 发布

### 8.2 内容自动化

使用 GitHub Actions 实现定时更新的标准步骤：

1. 编写 `workflow.yml`：定义触发条件（cron 表达式）和执行步骤
2. 编写更新脚本：生成或更新内容
3. 配置自动提交：在 workflow 中添加 `git add . && git commit && git push`
4. 首次运行后监控：确认 workflow 触发正常、提交正确

### 8.3 批量处理

对多个同类仓库执行统一操作：

1. 定义标准模板（文件结构、内容格式、配置规则）
2. 逐仓库或使用脚本批量应用模板
3. 抽样验证（检查 3-5 个仓库确认应用正确）

### 8.4 数据采集与整理

从外部数据源提取结构化信息的流程：

1. 定位数据源并确认访问方式（API、网页、文件）
2. 编写采集脚本，先在小样本上验证
3. 确认输出格式正确后扩展到全量
4. 结构化保存并沉淀到对应仓库
