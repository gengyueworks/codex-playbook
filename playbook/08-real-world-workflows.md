# 实战工作流

> 消化自雨哥 Codex 实战课第 27、28、29 节（工作流三节课：从演示最小工作流到 harness 心法，再到同骨架套不同行业），叠加作者自身实践经验。

---

## 从想法到成品的最小工作流

工作流的核心问题是：**没有工作流之前，你和 AI 的协作是散的。** 画图一个窗口、改稿一个窗口、写完复制到本地、不满意再让 AI 重来……改来改去，旧版本找不到，新版本不知道该放哪，格式在不同平台之间反复转换。最重要的是，你跟 AI 沟通过程中的思考过程、改稿习惯、第一稿到最后一稿的变化轨迹——全都没留下。

工作流要解决的，就是把这条链路标准化、可复用、可沉淀。

---

## 通用五步骨架

从课程第 29 节提炼的通用工作流模板：

| 步骤 | 做什么 | 示例 |
|---|---|---|
| 1 输入材料 | 把原始想法、素材、过往案例交给 AI | 一段想法、一篇旧文、一组客户反馈 |
| 2 AI 处理 | AI 按预设规则处理材料 | 初稿生成、格式转换、信息整理 |
| 3 规则核对 | 用预设规则检查输出 | 字数、语气、事实、格式 |
| 4 生成交付物 | 输出可直接使用的成品 | Markdown 文件、发布格式、通知稿 |
| 5 归档沉淀 | 保存到固定位置，形成可复用资产 | 存入项目目录、更新 Skill |

**这套骨架不局限于写文章。** 做选题策划、写周报、整理会议纪要、生成 PPT 大纲——任何"从模糊想法到清晰交付物"的任务，都能套这个五步。

## Harness 心法：给 AI 套上缰绳

LLM 的理解能力和生成能力很强，但它没有边界感——你不给它规则，它每次都可能偏离你的预期。Harness（马具）的概念就是：**给 LLM 套上规则，让它按你的标准工作。**

套上 harness 之后：
- AI 知道什么情况该读草稿、什么情况该直接生成
- AI 知道你的改稿习惯（你每次手动改什么，它就去学什么）
- AI 知道输出格式、命名规范、存档位置

**这就是"让工作流越用越懂你"的底层逻辑。** 不是 AI 变聪明了，是你给它套的规则在积累。

## 同一个骨架，套你自己的行业

课程里教的不是"怎么写文章"，而是"怎么把任何重复性工作变成可复用的流水线"。

比如课程用"写文章"演示了五步骨架，但你可以：
- 把输入材料换成客户反馈 → 自动整理成需求清单
- 把 AI 处理换成数据清洗 → 自动生成报表
- 把归档沉淀换成 GitHub 提交 → 自动更新项目文档

**学的是一套方法论，但你可以把它嫁接到你所在的行业和具体工作上。**

## 写作到仓库

将原创内容转化为开源项目的标准化流程：

1. 完成原创内容的 markdown 文件
2. 使用 Codex 生成项目骨架：README、目录结构、导航索引
3. 组织内容文件到对应的目录结构
4. 生成封面或入口页面
5. 执行 `git push` 发布

---

## 内容自动化

使用 GitHub Actions 实现定时更新：

1. 编写 `workflow.yml`：定义触发条件（cron 表达式）和执行步骤
2. 编写更新脚本：生成或更新内容
3. 配置自动提交：在 workflow 中添加 `git add . && git commit && git push`
4. 首次运行后监控：确认 workflow 触发正常、提交正确

---

## 批量处理

对多个同类仓库执行统一操作：

1. 定义标准模板（文件结构、内容格式、配置规则）
2. 逐仓库或使用脚本批量应用模板
3. 抽样验证（检查 3-5 个仓库确认应用正确）

---

## 数据采集与整理

从外部数据源提取结构化信息：

1. 定位数据源并确认访问方式（API、网页、文件）
2. 编写采集脚本，先在小样本上验证
3. 确认输出格式正确后扩展到全量
4. 结构化保存并沉淀到对应仓库
