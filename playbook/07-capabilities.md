# 能力扩展：Skill、Plugin、MCP

> 消化自雨哥 Codex 实战课第 21-24 节 Skill 专题（四节课完整覆盖从概念到串联工作流）及第 32 节 Skill 与插件入门。

---

## Skill 是什么

Skill 不是单个文件，而是一个**文件夹**，包含：

| 组件 | 说明 | 是否必需 |
|---|---|---|
| `SKILL.md` | 描述什么时候触发、做什么、有什么限制 | 必需 |
| `scripts/` | 自动化脚本（Python 等），AI 可调用 | 可选 |
| `references/` | 补充文档、范文、参考资料 | 可选 |
| `assets/` | 图片、截图、结构图等静态资源 | 可选 |

**一句话**：Skill = 你可以复用的提示词，加上固定的工作流程和配套资源。

以前，每一次做同类任务，你都要重新写一大段提示词。用了 Skill 之后，你只需要告诉 AI 调用，它会自动按你预设的流程工作。

**什么时候该把任务做成 Skill：** 当你发现自己每周、每天、甚至每几个小时都在做同一类事情——比如写日报、做选题、整理客户反馈——就值得把它沉淀成 Skill。

## Skill 的三种存在形式

| 类型 | 安装位置 | 生效范围 |
|---|---|---|
| 全局 Skill | `~/.codex/skills/` | Codex 里的所有项目都能用 |
| 项目级 Skill | 项目目录下的 `.codex/skills/` | 只在当前项目中生效 |
| 系统内置 Skill | Codex 自带 | 无需安装，直接调用 |

**区分建议**：通用型的（写作润色、选题灵感、通用模板）放全局；业务专用的（某个客户的风格规范、某个项目的内部流程）放项目级。

## 创建第一个 Skill：三步走

**第一步：先用提示词反复跑通。**
在对话中把提示词迭代到稳定可用的状态——不要一上来就创建 Skill。先确保"用提示词能稳定出好结果"，再来封装。

**第二步：让 AI 帮你生成 Skill 结构。**
把跑通的提示词和流程告诉 AI，让它帮你生成 `SKILL.md` 文件和相关目录。你不需要手写结构。

**第三步：实际调用测试。**
创建完成后，在新对话中调用这个 Skill，验证它是否按预期工作。跑几次、改几版，才能顺手。

## 优化 Skill 的三个方向

装完 Skill 不是终点，是起点。持续优化的三个方向：

1. **场景差异优化**：同一个 Skill 做公众号文章和小红书文案，用户画像和语气完全不同。根据场景增加不同的触发条件和输出约束
2. **流程细节优化**：实际使用中发现哪一步经常需要手动纠正，就把它写进 Skill 的规则里
3. **串联优化**：一个 Skill 的输出可以是另一个 Skill 的输入。比如"选题 Skill"→"初稿 Skill"→"改稿 Skill"→"发布格式 Skill"，形成完整内容生产线

## 三者关系

| 概念 | 职责 | 类比 |
|---|---|---|
| Plugin | 打包 Skill 和 MCP 为可安装单元，提供第三方服务能力 | 工具箱 |
| Skill | 定义同类任务的标准执行流程 | 说明书 |
| MCP | 连接外部工具或数据源 | 给工具箱接电的插座 |

**记住**：Plugin 负责打包和分发，Skill 负责"怎么做"，MCP 负责"连什么"。三者各管一层，不互相替代。Codex 内置了 5 个系统 Skill（写 README、代码 Review 等），你可以直接调用也可以在此基础上修改。

## 常用插件方向

| 类型 | 能力 |
|---|---|
| 浏览器操作 | Chrome, Computer Use |
| 代码协作 | GitHub |
| 前端设计 | Build Web Apps, Figma |
| 文档交付 | Documents, Presentations, Spreadsheets |
| 视频生成 | HyperFrames, Remotion |

**安装建议**：不需要装太多。只装你跟当前项目真正用得到的。插件多了反而拖慢启动速度和 Token 消耗。
