# 让项目自己跑起来

前面讲的都是你坐在前面、它干活的"手动模式"。Codex 还能设成定时自己跑——你睡了，它还在更新。

## 定时能干什么

比如一个每天更新一条的栏目、一个每周自动汇总一次的清单、一个每天去抓最新资料并整理的任务。设好之后不用你盯着，到点自己触发。

## 最大的坑：定时不一定准点

这是真事，不是吓你。GitHub 上的定时任务，官方明说不保证准点——可能延迟一两个小时，也可能某天根本没触发。你去查记录会发现不是执行失败，是压根没有触发这一条。

如果你做一个每天必须更新的栏目，靠单次定时，迟早会断更。

## 对策：两个时间点 + 跑过就跳过

做法是设两个触发时间，比如早上一次、中午一次。然后让脚本自己判断：**今天已经更新过了就跳过，没更新才补。**

两次都丢的概率极低。脚本跑两遍也不会出事，因为第二遍发现"已经更新了"就直接结束。这叫"幂等"——跑一次和跑多次结果一样。

```
0 0 * * *   每天零点尝试更新
0 6 * * *   每天六点再尝试一次
脚本逻辑：如果今天已有内容，直接退出；没有才生成。
```

## 定时只管"触发"，素材得你先备好

另一个常见误区：以为设了定时就万事大吉。其实定时只负责"到点喊一声"，内容从哪来、长什么样，得你提前把素材池和格式模板备好。素材空着，它到点也只能生成空壳。

## 验收定时靠查记录

别假设它跑了。隔几天去看一眼输出文件的时间戳，或者任务记录里有没有执行痕迹。发现某天断了，再调时间点或加一道保险。
