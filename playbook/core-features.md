# ## 一、Thread：一个任务一个对话

Thread 是 Codex 里的"任务对话"。

**项目 = 一个代码文件夹；Thread = 这个项目里的一个具体任务。**

比如项目是"小红书封面生成器"：
- Thread 1：做首页
- Thread 2：修复上传图片失败
- Thread 3：优化手机端布局
- Thread 4：写项目说明文档

**为什么要有 thread？**
不同任务最好分开做。把"做首页、修 bug、改样式、写文档"全塞进一个对话，Codex 容易上下文混乱，你也不好检查它到底改了什么。

**一句话总结：一个明确任务 = 一个 thread。**

### 我的用法

- 每接一个活儿，先想清楚这是一个任务还是多个任务
- 一个任务开一个 thread，做完归档（Archive），项目列表永远干净
- 发现新问题，新开 thread，不续旧对话

## 二、Sandbox 沙盒：Codex 的安全围栏

Codex 不是普通聊天工具——它能读文件、改文件、运行命令。所以必须有一个"围栏"限制它能碰哪里。

**沙盒决定 Codex 能不能：**
- 看文件
- 改文件
- 访问项目外目录
- 联网
- 运行高风险命令

**三个权限档位：**

| 选项 | 说明 | 风险 |
|---|---|---|
| 请求批准 | 越界操作先问你 | 安全，新手推荐 |
| 替我审批 | 让系统自动判断一部分审批 | 中等 |
| 完全访问权限 | 放开沙盒，随意操作 | 最高，不推荐新手 |

**我的建议：新手开"请求批准"。** 让 Codex 在项目内工作，但遇到越界、联网或高风险命令时停下来让你确认。别一上来就开完全访问权限。

## 三、插件、Skill、MCP：三者关系（最重要的一张表）

这三个概念最容易混淆。它们不是互相替代，而是**各管一层**：

| 概念 | 一句话 | 解决什么问题 | 类比 |
|---|---|---|---|
| 插件 Plugin | 能力安装包 | 安装、打包、分发能力 | 工具箱 |
| Skill | 一套固定工作方法 | 同类任务"怎么做" | 工具箱里的说明书 |
| MCP | 连接外部工具的接口 | "连接什么工具或数据" | 给工具箱接电的插座 |

**一句话记住：插件可以把 Skill 和 MCP 打包成更容易安装的能力包；Skill 管"怎么做"，MCP 管"连什么工具"。**

---

## 四、Skill 详解

Skill 是给 Codex 准备的一套**固定工作方法**。

Codex 本身会读代码、改代码、运行命令。但如果你经常让它做同一类任务——写 README、做代码 Review、生成网页、整理文档——就可以把这套流程做成 Skill。

**Skill 的组成：**

| 组成 | 说明 |
|---|---|
| Prompt | 这一次任务的提示词 |
| Workflow | 做事流程 |
| Template | 固定模板 |
| Instruction | 给 Codex 的长期规则 |
| Resource | Skill 里附带的参考资料 |
| Script | 可选的自动化脚本 |

**例子：README Skill**

你每次都想让 Codex 写 README，而且必须包含：项目介绍、安装步骤、启动命令、文件结构、常见问题。

那就做一个 README Skill。以后不用每次重新解释规则，只要调用这个 Skill，Codex 就会按这套流程写。

**一个文科生的理解：Skill = 你把"怎么干活"教给 AI 的说明书。** 我不会写代码，但我会把"我的写作标准、我的流程、我的模板"写进 Skill，让 Codex 按我的标准干活。

## 五、MCP 详解

MCP（Model Context Protocol）是连接外部工具的接口。

**它解决的是"Codex 怎么连上你的工具和数据"。**

- 数据库 MCP：让 Codex 直接查数据库
- 文档 MCP：让 Codex 读写你的文档系统
- 浏览器 MCP：让 Codex 操作浏览器

**我的理解：MCP 是给 Codex 接电的插座。** 你想让它用哪个工具，就插哪个插座。这个偏开发者配置，普通用户可以先不管，等需要了再研究。

## 六、常见插件和能力方向

| 类型 | 插件 | 主要作用 |
|---|---|---|
| 浏览器与电脑操作 | Chrome、Computer Use | 直接操作浏览器、像人一样看屏幕点按钮 |
| 代码与项目协作 | GitHub | 管仓库、修 bug、创建 PR |
| 前端与设计 | Build Web Apps、Figma | 一句话生成网页、设计稿转代码 |
| 办公交付 | Documents、Presentations、Spreadsheets | 正式文档、高质量 PPT、数据分析 |
| 视频生成 | HyperFrames、Remotion | HTML 生成视频、代码生成专业视频 |

> 插件目录会随版本变化，以你当前 Codex 插件页显示为准。

---

## 我的核心体会

这些功能看起来是给程序员准备的，但底层逻辑对任何用 Codex 的人都成立：

- **Thread** → 就是"一次只干一件事"，和我写作时分小节一样
- **沙盒** → 就是"安全边界"，让 AI 听话又不越界
- **Skill** → 就是"把标准教给 AI"，我的写作标准就是我的 Skill
- **MCP** → 先不用管，等需要了再说

**工具是工程师造的，但用法是属于每个人的。**
