# 把常用操作变成 Skill

用上一阵你会发现，有些活儿你每周都让 Codex 干一遍，每次都要把同样的要求重新说一次。这些就可以存成一个 Skill，下次一句话调出来。

## Skill 是什么

简单说，Skill 就是把"一套固定的操作 + 一套固定的要求"打包成一个模板。存好之后，你不用再重复交代，说一句"用某某 Skill 处理这个"就行。

它和规矩文件（AGENTS.md）不一样：规矩是"你干活要遵守的底线"，Skill 是"某一个具体任务的标准流程"。

## 三种做法

**从社区装。** 很多常见流程别人已经做好了，搜索一下直接装，比如"公众号标题生成""简历润色"这类。

**让它帮你生成。** 你把要做的事说清楚，它可以帮你把这套流程写成一个 Skill，下次直接调用。

**录下来。** 有些操作你已经在界面上走了一遍，可以用录制功能把这次操作流程存成 Skill，以后复现。

## 什么时候该做成 Skill

一个判断标准：**同一套话你每周都说一遍，就值得做成 Skill。**

比如你每周要把一堆散落的链接整理成带分类的清单，每次都要重新交代格式——这就该固化。做成 Skill 之后，格式稳定，你也不用每次重新教。

## 做 Skill 也要写边界

Skill 是好用，但有个坑：它把流程固化了，Codex 会严格照着模板走，也可能照模板把范围扩大。所以 Skill 里同样要写清楚"只处理哪些、哪些别碰"。

一个干净的 Skill 长这样：

```
目标：把收藏夹导出的链接，按主题分成几类，输出一个带小标题的清单。
输入：一个放满链接的文本文件。
输出：一个 markdown 文件，每类一个小标题，下面列链接和一句话说明。
边界：不删原文件，不改链接本身，只做分类和说明。
```

## 别囤太多

和规矩一样，Skill 不是越多越好。一个 Skill 如果用过两次再没碰过，说明它没解决你真会反复撞上的事，删掉。
