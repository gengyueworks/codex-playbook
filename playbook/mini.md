## 一、Codex 是什么

一个住在你电脑里的、会说人话的程序员。
我负责"要什么"，它负责"怎么实现"。**我是老板，它是员工。**

## 二、开始（3 分钟）

```bash
cd 你的项目
codex
```

说人话："帮我把这个 README 改得更吸引人一点"。

| 命令 | 作用 |
|---|---|
| `codex` | 交互模式 |
| `codex "任务"` | 直接派活 |
| `--full-auto` | 全自动 |
| `--ask-for-approval` | 每步问你（新手推荐） |

## 三、说人话公式

```
角色 + 任务 + 上下文 + 验收标准
```

差："帮我优化一下"
好："你是资深前端，把首页改成移动端适配，项目在 src/ 用 React，改完 375px 下按钮不溢出"

## 四、AGENTS.md —— 最重要的习惯

项目根目录建 `AGENTS.md`，写清楚规矩（语言、风格、提交规范）。Codex 每次干活先读它，不用重复交代。

## 五、Skills

把常用能力封装成技能包（写作润色、建仓库、定时任务），下次一句话触发。

## 六、三句话工作流

1. **写作 → 仓库**：文章交给 Codex 变项目
2. **内容自动化**：GitHub Action 定时更新
3. **批量化**：统一模板批量处理几十个仓库

## 七、五个坑

1. 不给上下文 → 先贴背景
2. 一次太多任务 → 拆小步
3. 以为它能读心 → 说清"好看"是什么
4. 不验证就信 → 让它跑验证，你抽查
5. 不敢纠正 → 直接说"这个不行，改成那样"

## 八、核心信念

> 工具不会替你创造，但工具能让你的创造落地。
