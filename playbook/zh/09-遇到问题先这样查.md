# 09 遇到问题，先这样查

Codex 用得越深，越会遇到失败。失败本身没有那么可怕，真正浪费时间的是一看到结果不对，就重新开始，最后不知道问题出在哪一步。

我批量处理雨哥课程的 35 个视频时，就经历过转录方案切换：网页转录服务没有正常工作，先判断账号和任务状态，再换成本地 Whisper，通过镜像下载模型，最后批量完成转录。中间每一步都需要留下判断依据。

## 先把问题说成现象

不要只说“它坏了”。先写四句话：

```text
我原本想完成：
实际看到的结果：
最后一次正常发生在：
我已经尝试过：
```

再让 Codex 只做诊断：

```text
先不要修改文件，也不要重试全部流程。
请根据现象列出最可能的三个原因，每个原因给出一个最小检查动作。
请标出哪些检查不会改变数据。
```

## 六种常见情况

| 现象 | 先查什么 | 处理方向 |
|---|---|---|
| 找不到文件 | 当前打开的文件夹和真实路径 | 重新打开正确项目，重新列目录 |
| 输出像是编出来的 | 来源、日期、数字是否存在 | 要求逐条标注来源，删除无来源内容 |
| 改动范围变大 | diff 和最近一次交代 | 恢复多余改动，缩小允许修改的位置 |
| 自动化突然停了 | 最近一次日志、权限、输入时间 | 先复现一个日期，再决定是否改脚本 |
| 批量任务漏文件 | 总数、分页、失败清单 | 加计数和失败记录，分批重跑 |
| 结果格式不一致 | 规则文件和上一份成品 | 把重复标准写进规则或 Skill |

## 转录方案切换的判断顺序

批量任务遇到失败，可以按这个顺序：

1. 先确认原始文件是否完整。
2. 只用一个小文件测试当前工具。
3. 看错误是账号、网络、格式还是模型问题。
4. 换方案前保存已经成功的结果和失败清单。
5. 换方案后仍然只用一个文件验证，再扩大批量。

如果一次跑 35 个视频，最后只看到“完成”，你无法知道有没有漏掉第 17 个。每个批量任务都应该输出总数、成功数、失败数和失败文件名。

## 什么时候应该停下来

遇到以下情况，先暂停并保留现状：

- 需要删除原始资料才能继续。
- 需要把私人数据发给外部服务。
- 需要扩大账号权限或推送到公开仓库。
- 你无法判断结果是否正确。

暂停不是放弃。留下现象、日志、当前文件和下一步检查，下一次对话可以从这里继续。

## 一份最短错题记录

```markdown
# 2026-08-11 转录批量任务

现象：网页转录任务没有产生可下载文本。
已确认：原始视频完整，单个文件上传也失败。
尝试：检查账号状态，保存失败清单。
下一步：用本地方案测试一个文件，再决定是否批量。
```

把解决方法写下来，下一次就不用从头猜。严重问题还可以把规则补回 AGENTS.md 或 Skill，让系统获得一次真正的改进。
