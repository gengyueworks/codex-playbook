# 02 第一次让 Codex 把一件事做完

上一章写下的三句话，还只是一个想法。现在把它变成一次真正的交代。

这次练习使用仓库里的公开素材。它们在 `examples/01-first-task/input/`，包括一份产品想法、一段会议记录和一条旧备忘。目标是把三份材料整理成一份可以继续工作的清单。

## 先把工作的地方打开

在 Codex 里打开 `examples/01-first-task/` 这个文件夹。第一次做任务时，先让它看现场，再让它动手。

你可以直接这样说：

```text
请先阅读 examples/01-first-task/input/ 里的三份 Markdown 笔记。

我的目标是把它们整理成一份可以继续使用的工作清单。

请先告诉我：
1. 你读到了哪些文件；
2. 你准备把结果写到哪里；
3. 你会怎样避免改动原始材料；
4. 你还缺哪些信息。

现在先不要创建或修改文件，只给我处理计划。
```

你要看到的结果，是 Codex 先列出文件和做法。它直接开始写文件时，你可以补一句：“先停在计划这里，等我确认后再动手。”

## 再交代具体产出

计划看过之后，再给第二段：

```text
按照刚才的计划继续处理。

请完成以下工作：
1. 提取每份笔记里的已知事实、待办事项和仍然不确定的问题；
2. 合并重复内容，并保留来源文件名；
3. 在 examples/01-first-task/output/ 下生成「整理结果.md」；
4. 文件包含四个部分：已确认信息、待办事项、待确认问题、来源索引；
5. 每条待办包含事项、负责人、截止时间和来源；材料没有提供的内容写“未提供”；
6. 不修改 input/ 下的原始文件，不编造材料里没有的人名、日期和结论；
7. 完成后说明创建了什么、检查了什么、哪些地方仍需要我判断。
```

这里有一个很重要的变化：你交代的是“要留下什么结果”，不是只说“帮我整理一下”。

## 完成后看三处

打开 `examples/01-first-task/output/整理结果.md`，再检查：

1. 三份输入文件都出现在来源索引里。
2. 材料没有写负责人和日期的地方，确实标成“未提供”。
3. `input/` 下的原始文件没有被修改。

如果你使用 Git，还可以让 Codex 给出改动清单：

```text
请列出本次创建和修改过的全部文件，并说明每个文件为什么发生变化。
请再次比较 input/ 和 output/，确认原始材料没有被改动。
```

“已完成”这句话只有在你能打开结果、看到来源、确认原文件还在时才有意义。

## 如果结果不对

- 输出文件为空：先让 Codex 重新读取输入目录，并报告每个文件的字符数。
- 出现材料里没有的人名或日期：要求它逐条标注来源；找不到来源的内容删除或标成“未提供”。
- 原始文件被改动：停止后续操作，先用 Git 或备份恢复，再把“只读 input/”写进下一次交代。
- 输出结构混乱：先只要求它列出四个标题，确认结构后再填内容。

## 本章结业

你完成本章，应该已经亲手经历一次完整的小任务：打开文件夹、交代结果、等待计划、查看文件、检查原始材料。
