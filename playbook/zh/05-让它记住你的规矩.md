# 05 让它记住你的规矩

每次都重新解释“中文用什么标点、README 要不要英文、改完要不要检查”，很快就会累。项目里可以放一份 `AGENTS.md`，把这些长期有效的规矩写下来。

它不是一份神奇的记忆。它更像贴在工作台旁边的说明：Codex 进入这个文件夹后，先读这里，再开始工作。

## 先写真正长期有效的内容

我的项目规则通常包含这些东西：

- 这是什么项目，读者是谁。
- 文章使用什么语言和标点。
- README 是否需要中英双语。
- 哪些目录是原始资料，不能直接改。
- 每次写完要做哪些检查。
- 哪些动作必须先让我确认，例如发布、删除和批量改动。

规则越接近真实习惯，越有用。把所有想得到的要求都塞进去，文件会变成没人愿意读的大杂烩。

## 一个适合内容项目的版本

```markdown
# 这个项目怎么工作

## 项目说明

- 这是一个面向普通读者的中文内容项目。
- 每篇文章都要有清楚的标题、来源和发布日期。

## 写作习惯

- 使用自然、直接的中文。
- 中文正文使用中文标点。
- 少用抽象口号，多写具体事实和动作。
- 重要数字、日期、链接必须回到来源核对。

## 文件习惯

- 原始资料放在 input/，只读，不在原文件上改稿。
- 成品放在 output/，文件名清楚，目录保持整齐。
- README 需要同时提供中文和英文入口。

## 交付前检查

- 列出新增和修改的文件。
- 检查链接是否存在。
- 检查原始资料没有被改动。
- 展示 diff。
- 发布、删除和批量改动前等待人工确认。
```

这份规则故意保持短小。等你真的遇到一次重复问题，再把解决办法补进去。

## 放在哪里

通常可以这样理解：

- 放在项目根目录，影响整个项目。
- 放在更深的子目录，只约束那一块内容。
- 多层规则同时存在时，越靠近当前文件的说明越具体。

实际读取范围会受 Codex 当前入口和项目结构影响，所以第一次使用时，可以直接问：“你找到了哪些 AGENTS.md？接下来会遵守哪几条？”

## 让 Codex 帮你写第一版

把你过去三次返工的原因告诉它：

```text
请根据这个项目最近三次返工记录，起草一份简短的 AGENTS.md。

只写长期有效、可以检查的规则。不要把一次性的任务要求写进去。
规则按项目说明、写作习惯、文件习惯、交付检查四组排列。
先展示草稿，不要覆盖已有文件。
```

你审核过后，再让它写入。以后每次遇到同一种错误，优先考虑补规则，而不是每次在对话里重复提醒。

## 规则失效时怎么办

- Codex 没有读到规则：确认文件名、位置和当前打开的项目。
- 规则写得太宽：改成“只做什么、在哪做、怎样检查”。
- 规则之间冲突：保留一条明确版本，删除旧说法。
- 规则越来越长：把操作细节移到 Skill 或项目说明，AGENTS.md 只保留入口和硬要求。
