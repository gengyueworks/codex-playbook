# 06 把常用操作变成 Skill

如果你每周都让 Codex 做同一类事情，就值得把这套做法留下来。

Skill 可以理解成一个装着说明、参考资料和辅助脚本的小文件夹。它把“我通常怎么做”变成下次可以再次调用的工作说明。

## 先跑通，再保存

雨哥课程里有一个很实用的顺序：先用自然语言把事情做完，再让 Codex 总结出可重复的方法，最后拿另一份材料测试。

以“文章整理成公开发布稿”为例，先明确五步：

1. 输入材料：原始笔记、来源链接、作者补充。
2. AI 处理：整理结构、补标题、提出缺口。
3. 规则核对：事实、语气、格式和隐私。
4. 生成交付物：正文、README、来源说明。
5. 归档沉淀：放到正确目录，并留下日期和版本。

这套顺序跑过几次以后，再写 Skill。过早保存的 Skill，通常只是一个漂亮的空壳。

## 一个最小目录

```text
article-publishing/
├── SKILL.md
├── references/
│   └── writing-checklist.md
└── scripts/
    └── check-links.sh
```

`SKILL.md` 只需要说明四件事：什么时候使用、需要哪些输入、按什么步骤做、交付前怎样检查。参考资料和脚本分别放在自己的目录，不要把所有内容堆进一个长文件。

## 最小的 SKILL.md

```markdown
# 文章整理与发布

## 什么时候用

当输入是一篇或多篇原始笔记，需要整理成可以发布的 Markdown 文章时使用。

## 输入

- 原始材料路径。
- 文章主题和目标读者。
- 必须保留的事实与来源。
- 发布目录。

## 步骤

1. 读取原始材料，列出事实和缺口。
2. 先给出文章结构，等待确认。
3. 按项目规则写初稿。
4. 检查事实、链接和敏感信息。
5. 输出文章、来源说明和改动清单。

## 禁止

- 不把缺失事实补成确定结论。
- 不覆盖原始材料。
- 不在没有确认时发布或推送。
```

## Skill 和 AGENTS.md 怎么分

记住一个简单区分：

- AGENTS.md 讲“这个项目长期遵守什么”。
- Skill 讲“遇到这一类工作具体怎么做”。

一个项目可以有一份规则，也可以有多个不同用途的 Skill。以后你维护几十个同类仓库时，模板和 Skill 会把重复解释压缩下来，但每个项目仍然要保留自己的事实和例外。

## 第一次测试

创建 Skill 后，不要只看文件写得像不像。拿一份新材料调用它，并记录：

- 它有没有找到输入文件。
- 它是否真的按步骤先给结构再写稿。
- 它有没有跑完检查。
- 哪一步仍然需要你手动补充。

把测试结果写回 Skill。能被新材料验证的说明，才算真正有用。

## 本章练习

选一个你最近做过三次以上的重复任务：整理会议、维护 README、准备文章、批量改文件都可以。先让 Codex 写出一份 Skill 草稿，再用第二份材料测试。保留“第一次版本”和“测试后版本”，你会清楚看到方法怎样变得具体。
