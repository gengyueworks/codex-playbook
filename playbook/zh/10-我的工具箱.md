# 10 我的工具箱

走完前面的章节，你已经拥有一套可以反复使用的工作方式：先把想法说出来，再让 Codex 读材料、问问题、做小步修改，最后自己检查并把方法留下来。

这一章只保留真正会用到的东西，不做功能名词大集合。

## 五分钟任务卡

```text
我要完成：
目标读者或使用者：
手边材料：
允许修改的位置：
必须保留的事实：
完成后我会检查：
暂时不要做：
```

## 让 Codex 先问问题

```text
我有一个想法，但信息还不完整。
请先向我提出最重要的 5 个问题，按“如果不确认就无法继续”的顺序排列。
先不要给最终方案，也不要修改文件。
```

## 让 Codex 先给计划

```text
请先阅读相关文件，告诉我你准备分几步完成。
每一步写清会读什么、会生成或修改什么、我应该在哪里检查。
现在只给计划，等我确认后再执行。
```

## 让它交付证据

```text
任务完成后请汇报：
1. 创建和修改过的文件；
2. 每个文件发生变化的原因；
3. 运行过的检查和结果；
4. 仍然缺少的事实或需要我决定的事项；
5. 如果任务失败，保留失败清单和下一步建议。
```

## 我的学习路线

第一次使用：先做第 02 章练习，再读第 03 章。

已经会交代任务：读第 04、05 章，把自己的项目规则写下来。

重复工作很多：读第 06、07 章，先手动跑顺，再做 Skill 或自动化。

经常处理资料：读第 08、09 章，给每次批量任务留下数量、来源和失败记录。

## 最后一条经验

Codex 的价值会随着你的材料、规则和经验一起增长。你每次认真检查一次结果，就多了一条以后可以复用的判断；你每次把重复步骤写下来，就少了一次从空白开始。

我更愿意把自己称为 coder 世界里的吟游诗人：别人交付功能，我把故事、知识和想法做成公开作品。Codex 让这些作品有机会从脑子里走出来，进入真实的文件夹、仓库和读者面前。

你可以从一篇文章、一个文件夹或一次会议记录开始。先让它起个头，再一起把事情做完。

## 本章结业

- [ ] 我能写出一张五分钟任务卡。
- [ ] 我会让 Codex 先提问、先给计划，再开始修改。
- [ ] 我会在交付时查看文件、检查结果，并留下下一次可以使用的说明。
