## 第一章：Codex 是什么

Codex 是 OpenAI 的编程 agent。你可以把它理解成：

**一个住在你电脑里的、会说人话的程序员。**

- 你在终端里跟它说话
- 它读你的项目文件、改代码、跑命令
- 你盯着它干活，随时纠正

它不是"自动生成代码的玩具"，它是**能自己动手完成一个任务的助手**。

### 文科生视角

程序员觉得 Codex 是"更快写代码的工具"。
我觉得 Codex 是"**把想法变成现实的手**"。

我不会写代码，但我知道自己要什么。Codex 负责"怎么实现"，我负责"要什么、好不好用"。

**这是分工，不是替代。** 我是老板，它是员工。

## 第二章：怎么开始（3 分钟）

### 1. 安装

- **官方 App**：OpenAI 官网下载 Codex App（macOS / Windows）
- **CLI**：终端里装 `codex` 命令行工具（官方支持）
- **网页版**：在 ChatGPT 里也能用 Codex（Pro 用户）

### 2. 登录

用你的 OpenAI 账号登录。需要 ChatGPT Plus 或 Pro 订阅。

### 3. 第一次对话

打开终端，进入你的项目目录：

```bash
cd 你的项目
codex
```

然后直接说人话：

```
帮我把这个 README 改得更吸引人一点
```

它就会开始干活。**第一句话怎么说都行，说人话就行。**

### 4. 常用命令

| 命令 | 作用 |
|---|---|
| `codex` | 进入交互模式 |
| `codex "任务描述"` | 直接派活 |
| `codex --full-auto` | 全自动模式（自己干完） |
| `codex --ask-for-approval` | 每个改动问你（推荐新手） |

## 第三章：说人话的秘诀

Codex 不是搜索引擎。你给它越具体的指令，它干得越好。

### 好指令 vs 差指令

| 差 | 好 |
|---|---|
| 帮我优化一下 | 帮我把首页标题改成更口语化的风格，用户是小学生 |
| 修个 bug | 打开 login.js 第 42 行，登录按钮点了没反应，帮我查原因 |
| 写个 README | 写一个英文 README，开头用一句话介绍项目，分三节：安装、使用、常见问题 |

### 万能公式

```
角色 + 任务 + 上下文 + 验收标准
```

例子：

> 你是资深前端（角色）。帮我把这个网页改成移动端适配（任务）。
> 项目在 src/，用的 React + Tailwind（上下文）。
> 改完在 375px 宽度下所有按钮不溢出，能正常点击（验收标准）。

### 给上下文

Codex 会读你项目里的文件，但它不知道你脑子里的东西。**把背景说清楚：**

- 这个项目是干嘛的
- 你之前试过什么
- 为什么想要这个效果

## 第四章：AGENTS.md —— 让 Codex 记住你的规矩

这是我最喜欢的功能。在项目根目录建一个 `AGENTS.md`，写清楚规矩，Codex 每次干活都会先读它。

### 我的 AGENTS.md 长这样

```markdown
# 项目规矩

## 语言
- 所有文案用中文
- README 用中英双语

## 风格
- 口语化，不要 AI 腔
- 不用"赋能、抓手、闭环"这类黑话

## 代码
- 不要为了跑通而注释掉报错
- 改完要跑验证

## 提交
- commit message 用英文，简洁
```

### 效果

- 不用每次重复交代
- 项目越多越省心
- 换新项目复制一份改改就行

**这是从"会用它"到"用得好"的第一个分水岭。**

## 第五章：Skills —— 把常用能力封装起来

Skills 是 Codex 的"技能包"。把经常干的事封装成一个 skill，下次一句话就能调。

### 我能想到的用法

| Skill | 干什么 |
|---|---|
| 写作润色 | 一段文字丢进去，按我的风格改 |
| 建仓库 | 说个想法，自动生成项目结构 + README |
| 内容定时 | 每天自动跑任务、提交更新 |
| 翻译 | 中英互译，保持语气 |

### 怎么用

1. 在 `.codex/skills/` 目录建一个文件夹
2. 写一个 `SKILL.md` 描述这个技能干什么、怎么做
3. 下次对话里提到就能触发

## 第六章：实战工作流

### 工作流一：写作 → 仓库

我写的每一篇长文，最后都会变成一个开源仓库：

```
1. 我写文章（markdown）
2. 让 Codex 建仓库骨架（README、目录结构）
3. 让 Codex 把文章组织进去
4. 自动生成封面/导航
5. push 到 GitHub
```

### 工作流二：内容自动化

用 GitHub Action + Codex 做定时任务：

```
1. 写一个 workflow 文件（让 Codex 帮你写）
2. 设置定时（每天早上 8 点跑）
3. 任务：生成/更新内容
4. 自动 commit + push
```

我有个项目每天自动更新科学人物日历，已经连续跑了一个月。

### 工作流三：批量化

我有几十个同类仓库（旅行、音乐、书单）。让 Codex 按统一模板批量处理：

```
1. 定一个模板
2. 让它按模板批量改
3. 抽查验证
```

## 第七章：常见坑（血泪经验）

### 坑 1：不给上下文就派活

**现象**：它自己瞎编，结果完全不是你要的。
**解法**：先贴背景，再派活。上下文越全，效果越好。

### 坑 2：一次塞太多任务

**现象**：干到一半忘了前面，或者虎头蛇尾。
**解法**：拆小步。一个对话干一件事，干完验收再下一个。

### 坑 3：以为它能读心

**现象**："帮我改好看点"——它改完你觉得丑。
**解法**：说清楚"好看"在你心里是什么。给参考、给例子、给方向。

### 坑 4：不验证就信它

**现象**：它说"搞定了"，实际没跑通。
**解法**：让它自己跑验证，你抽查关键输出。它是助手，你要做质检。

### 坑 5：不敢纠正它

**现象**：它做错了，不好意思说，将就着用。
**解法**：直接说"这个不行，改成那样"。它不会记仇。**纠正越具体，下一次越准。**

## 第八章：文科生用它到底干什么

最后，说说我真实的用法。**我不是在"学习编程"，我是在"创作"。**

- 我的旅行故事，变成了开源旅行指南
- 我的音乐随笔，变成了音乐专栏仓库
- 我的 AI 想法，变成了可运行的小项目
- 我的每日写作，变成了自动更新的内容站

Codex 没有让我变成程序员。它让我**作为一个写作者，拥有了把想法落地的能力。**

这就是我想在这本手册里传递的：

> **工具不会替你创造，但工具能让你的创造落地。**
> The tool won't create for you — but it lets your creation land.
