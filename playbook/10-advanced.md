# 10. 进阶用法：超越代码补全

## 10. 进阶用法：超越代码补全

大多数人的用法停留在"打开项目→描述需求→等它改代码"。这当然已经很强，但就像买了一台高性能电脑只拿来看网页——只发挥了 Codex 一小部分能力。本章汇集了从实战中验证过的高级用法，每一项都指向同一个核心：**把 Codex 从"代码生成工具"升级为"长期协作的开发助手"。**

### 10.1 先读项目，再动手

打开一个新项目时，不要直接派任务。先用以下指令建立全局认知：

```
先不要修改任何文件，帮我分析项目结构：
包括技术栈、目录职责、核心模块、启动流程，以及可能存在的问题。
```

这一步相当于让 AI 花少量 Token 画一张地图。后续任务的准确率会明显提升。否则它可能新建重复文件、修改错误模块、破坏原有设计。

### 10.2 先设计方案，再写代码

将单步指令"帮我实现 X"拆为三步：

1. 让它设计方案（列出 2-3 种方案，比较优缺点，不要修改代码）
2. 你选择一个方案并确认
3. 让它按选定方案实现

例如，不要说"增加用户权限系统"，而是：

```
先分析目前权限相关代码，给出 3 种实现方案，比较优缺点，不要修改。
```

确认方案后，再执行：`按方案 2 开始实现`。

原因是：AI 最怕的不是不会写代码，而是不知道你到底想要什么。方案前置让双方对目标有一致理解。

### 10.3 任务拆分：降低 Token 消耗

"帮我重构整个后台"——这句话范围太大，Codex 需要不断读取大量文件，上下文越来越长，Token 自然膨胀。

改为拆分成多个独立任务：

1. 第一轮：分析数据库层的问题
2. 第二轮：优化接口设计
3. 第三轮：重构前端组件
4. 第四轮：补充测试

每轮完成后提交一次，再进入下一轮。不仅省 Token，且每轮的交付质量更稳定。

### 10.4 维护项目专属的 AI 说明文档

Codex 每次进入项目，都像一个新员工——它不知道你的代码习惯、项目规则、命名方式、部署流程。

在项目中维护一个说明文件（如 `PROJECT_CONTEXT.md`），包含：

- 项目介绍与技术栈
- 开发规范与命名约定
- 哪些文件绝对不能修改
- 测试方式与常用命令
- 常见问题与踩坑记录

每次启动任务前，让 Codex 先读这个文件。相当于给 AI 做了一次入职培训，效果非常明显。

### 10.5 用 Codex 做"代码侦探"

线上出现 Bug 时，传统流程是：看日志 → 搜索代码 → 猜问题 → 半天过去。

Codex 可以直接：

```
根据这个错误日志，帮我定位可能的问题路径。不要修改代码，只分析。
```

它经常能快速缩小问题范围，尤其在接手别人遗留项目时，这个能力让排查效率成倍提升。

### 10.6 用 Codex 生成测试

开发者普遍不喜欢写测试——重复、枯燥。但 AI 特别适合这种工作：

```
给这个接口生成完整测试，包括正常情况、异常情况、边界条件。
```

它不会嫌麻烦。让它生成 100 个测试用例，它不会有任何怨言。测试覆盖的价值，往往超过让它多写一个业务功能。

### 10.7 用 Codex 做代码审查

提交代码之前，让 Codex 以审查者视角检查：

- 安全问题
- 性能隐患
- 隐藏的边界 bug
- 是否违反项目规范

很多时候，它发现的潜在问题比自动补全更有价值。

### 10.8 角色模拟：多个视角审查同一段代码

同一个功能完成后，让 Codex 分别扮演不同角色审视输出：

- **产品经理**：从用户体验角度挑问题
- **测试工程师**：找出可能出 Bug 的地方
- **安全工程师**：检查漏洞
- **架构师**：看长期可维护性

用多个视角检查同一段代码，发现的问题比单一视角多一个量级。

### 10.9 每完成一个阶段就提交

AI 写代码最大的风险不是写得慢，而是改得太快——10 分钟改了一堆文件，最后发现方向错了。

- 每完成一个阶段用 Git 提交一次
- 或者让它总结本次修改内容并列出修改文件列表
- 不要让 AI 把整个项目变成你无法追踪的黑盒

### 10.10 Subagent：便宜模型做脏活，主力模型做决策

Codex 的 subagent 机制允许主 Agent（如 GPT 5.6 Sol）与子 Agent 使用不同的模型。例如，可以将 DeepSeek V4 Flash 配置为 subagent 来处理搜索、枚举、资料整理等 Token 密集型任务，让主力模型专注于需要深度推理的决策工作。

关键优势：
- Subagent 拥有独立的 model 和 provider 配置
- 不需要切全局模型，不需要第三方配置切换工具
- 任务传递、工具调用、权限管理仍由 Codex 统一管控
- 大幅度降低 Token 成本

配置完成后，一个任务中两个模型各司其职，成本可控、效率更高。

### 核心理念

Codex 真正改变的不是"程序员不需要写代码了"，而是工作重心的转移：

| | 以前 | 以后 |
|---|---|---|
| 写代码 | 70% | 30% |
| 设计、判断、Review | 30% | 70% |

**Codex 最强的地方不是替你敲键盘，而是把机械性工作拿走，让你把精力放在真正需要判断力的地方。** 如果只是把它当成"帮我生成代码的工具"，只发挥了一小部分能力。真正高级的用法，是把它培养成一个了解你项目、理解你习惯、能够长期协作的开发伙伴。
