# 让它记住你的规矩

用一段时间就会发现，每天在重复同样几句话：文件位置写全、别写成公文腔、改完自己检查一遍。第二天开个新窗口，又得从头说一遍。

这些话可以写进一个文件放在项目文件夹里，它每次干活前会自己看一眼。

## 文件叫什么，放在哪

固定叫 `AGENTS.md`，放在项目文件夹的最外层。

在 Codex 里打 `/init`，它会读一遍你的文件夹先生成一版。生成的那版基本是通用套话，真正管用的得自己往上加。

## 一条规矩怎么写

三部分：**要它干什么、错的样子长什么样、为什么。**

举个最常遇到的。它告诉你文件位置时经常只给个文件名，你不知道在哪个文件夹，点不开也复制不了。写成规矩是这样：

```
文件位置一律写完整路径。

错：周报-0413.md
错：./文档/2026-04/周报-0413.md
对：/Users/用户名/文档/2026-04/周报-0413.md

为什么：写一半没法点开，也没法复制。
```

**"为什么"别省。** 写了原因，它碰到你没写到的情况会自己往下推。只写"要写全路径"，它可能觉得聊天里随口提一句不算数；写了"因为要点开"，它就明白凡是需要点的地方都得写全。

**反例别省。** 抽象要求容易理解偏，摆一个错的样子，比多写三行说明管用。

## 可以先抄进去的六条

不知道写什么就从这几条开始，都是不挑项目的：

```
1. 回答和文案一律用中文，口语一点，别写成公文。
2. 提到任何文件，写完整路径。
3. 动手之前先说打算怎么做，等我说行再动。
4. 只改我指名的地方，其他一个字都别动。
5. 拿不准的时候停下来问我，不要自己决定。
6. 改完把动过的地方列出来，删掉了什么单独说。
```

第 4 条和第 6 条最值钱。它干活时容易顺手把旁边看着不顺眼的地方一起改了，这两条一个防、一个查。

## 三种会反复撞上的情况

**它会重新造一个你已经有的东西。**

你手上有什么它不一定认得全，同一个东西你在不同地方可能叫过不同名字，它没法猜，于是新建一个。等你发现，已经多出一个半空的重复品。

规矩：新建任何东西之前，先把现有的列一遍，确认没有能用的再建。

**它会顺手改你没让它改的地方。**

这是最常见的翻车。它为了把当前这件事做漂亮，会连带调整旁边的内容，而你根本没提过那部分。

规矩：写清楚这次只动哪里，其余不许碰。每次都写，不嫌烦。

**它会把文件全堆在最外层。**

批量生成和定时任务尤其明显。跑上一个月，最外层平铺几十上百个文件，滚半天到不了底。

规矩：同类文件超过十个就收进文件夹，按月份或者按系列分。生成的时候直接写进子文件夹，别先堆着回头收拾。

## 两层作用范围

放在项目文件夹里的，只管这个项目——比如这个项目的文章要中英双语。

放在 `~/.codex/AGENTS.md` 的，管你所有项目——比如上面那六条。

两层同时存在会叠加生效，不冲突。

## 别越写越长

规矩不是越多越好。它每次干活前都要读一遍，写太多反而把重点稀释了。

加进去之后再没派上用场的那条，删掉。
