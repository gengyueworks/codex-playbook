# 案例：从一篇文章到一个仓库

> 场景：我写了一篇长文，想把它变成一个正式的开源项目。
> 一小时内完成，全程没手写代码。

---

## 要做什么

我写了一篇"商业模式解剖"的长文。想把它变成一个仓库，能看、能传播、以后能继续维护。

## 我做的

### 1. 建仓库

让 Codex 创建项目骨架：

```
商业模式解剖
├── README.md        ← 中英双语介绍
├── articles/        ← 文章 markdown
└── index.html       ← 在线阅读页
```

### 2. 写 README

指令（说人话）：

> 写一个 README：开头一句话说明这个仓库收集什么；分三节——这是什么、怎么读、怎么贡献；风格口语化，中英双语。

### 3. 组织文章

把草稿丢进去，让它按统一格式整理。

### 4. 加封面和导航

让它生成一个 index.html，把多篇文章做成导航列表。

### 5. 推到 GitHub

```bash
git add .
git commit -m "init: business model forensics collection"
git push
```

## 用时

约 1 小时。其中 50 分钟是"我决定内容"，10 分钟是"Codex 干活"。

## 关键经验

- **内容质量是核心**：Codex 负责形式，我负责内容
- **README 决定第一印象**：值得花时间打磨
- **模板化**：第二次做同类仓库，直接把第一次的 AGENTS.md 和结构复制过去

## 迁移到你的场景

写作者：文章 → 仓库
研究者：资料 → 开源文档
老师：课程 → 教材仓库
任何人：想法 → 可落地项目
